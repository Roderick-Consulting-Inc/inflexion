# Inflexión

A hand-built esoteric programming language whose semantics flow from the grammatical features of Rioplatense Argentine Spanish — number, mood, aspect, the *ser* / *estar* split, clitic ordering, and diminutive / augmentative morphology — rather than from a vocabulary skin laid over an English-derived execution model.

The natural-language-themed esoteric programming language corpus is overwhelmingly English in its cultural references, and where it engages non-English material it does so almost exclusively through vocabulary substitution. Mierda, La Weá, and Chespirito are useful Spanish-flavoured precedents for vocabulary engagement. Wenyan is the most serious precedent we have found for grammatical engagement, and Wenyan operates over Classical Chinese — a literary register, no longer a living vernacular. We are not aware of any esoteric programming language that uses the grammar of a *living* non-English natural language as the source of programming semantics; we welcome correction.

Inflexión proposes one.

A program written in Inflexión that reads as Spanish prose to a Spanish-speaking reader is, simultaneously, a program in which **mood** distinguishes eager evaluation (indicative) from deferred evaluation (subjunctive) from side effects (imperative); **aspect** distinguishes eager from lazy (perfective vs. imperfective); ***ser* and *estar*** distinguish immutable bindings from mutable ones; **number agreement** carries the scalar-versus-collection distinction across articles, nouns, adjectives, and verbs in lockstep; **clitic ordering** routes function arguments through their fixed Spanish positional order; and **diminutive and augmentative morphology** scales numeric values and annotates function cost.

The language is hand-built rather than generated by [Babel](../Babel/), the companion methodology paper's runtime — a deliberate choice, so the language design is free of any tooling limits not yet discovered. Babel will be checked retroactively against Inflexión, not the other way.

## What this is and is not

Inflexión is an *esoteric* programming language, not a production language. It is not a localisation effort — Spanish-speaking developers already program comfortably in mainstream languages, and Inflexión is not addressing access. It is not a manifesto against English-keyworded programming. It is not, primarily, an LLM-prompting research project, though one section (`05` §5) develops a hypothesis about why a language whose surface syntax mirrors a more grammatically dense natural language may be a denser substrate for LLM prompting than English-keyworded equivalents.

The language is in its design phase. The first installment lays out the grammatical-semantic mappings and the design intent. A second installment, in planning, will give the operational semantics — the abstract machine, evaluation order, and a formal Turing-completeness argument — at which point a working interpreter will exist. A third installment, deferred, will run the empirical LLM-prompting study the design hypothesises about.

## Runtime status

The Python interpreter is being built in phases that track the six grammatical mappings from `05` §3 and the worked examples from `05` §5. As of v0.0.9, **Phase 8 has shipped: all six grammatical mappings plus Turing completeness plus the *decir* / *hablar* distinction on imperative output are implemented end-to-end**:

| Phase | Mapping covered | Example files | Status |
|---|---|---|---|
| 1 | *ser* binding + 1-clitic vos imperative (§3.1, §3.6) | `hello-mundo.infl` | shipped |
| 2 | *estar* binding + imperative mutation (§3.1, §3.6) | `contador.infl` | shipped |
| 3a | *Cuando* subjunctive deferred binding (§3.2) | `contador-listo.infl` | shipped |
| 3b | *Mientras* iteration + arithmetic (§3.2, §3.7) | `contador-cuenta.infl` | shipped |
| 4 | Number agreement + collections + broadcasting (§3.6, §3.7) | `precios.infl` | shipped |

| 6 | Diminutive / augmentative scaling + aspect-marked lazy (§3.3, §3.5) | `sumita.infl`, `potencias.infl` | shipped (v0.0.7, `1671465`) |
| 7a | Si-entonces-sino conditional dispatch; y-que multi-clause loop body (§3.2, §3.7) | `fizzbuzz.infl`, `fibonacci-iterativo.infl` | **shipped (v0.0.8, `bb441df`)** |

| 8 | `Hablá` (speak — ongoing activity, no auto-newline) sibling of `Decí` (say — committed content, terminated utterance). BF interpreter rewired to emit single-line `Hello World!` | `brainfuck.infl` (updated) | **shipped (v0.0.9)** |

238 tests passing as of Phase 8. The runtime is hand-built (Python + spaCy `es_core_news_sm` morphology + a custom rule layer for vos imperatives and irregular bare-stem resolution). Source lives in `src/inflexion/`; tests in `tests/`; runnable example programs in `examples/`.

With Phase 8, the imperative-output mapping carries the *decir* / *hablar* distinction Spanish itself carries: `Decí` commits to a content utterance and terminates it (appends `\n`); `Hablá` engages in ongoing speech, sound by sound, with no inherent termination. Both are vos imperatives under the mood mapping; the verb choice selects the content-vs-activity axis. The Brainfuck interpreter's `.` operator now uses `Hablá`, so `Hello World!` renders on a single line — matching standard BF host behaviour. The operational-semantics installment (Installment 06) is now unblocked and can be drafted from the captured implementation specification.

## Naming

The language was carried under the placeholder `«»` through the first complete draft and named *Inflexión* on 2026-05-09. The naming exercise — what the four candidate dimensions were, why the *mechanism* dimension won, and why *Inflexión* specifically over *Flexión*, *Concordancia*, *Conjugación*, and *Morfema* — is documented in `05` §11. The directory is `/data/rci/Inflexion/` (ASCII-safe); the language name keeps the accent.
